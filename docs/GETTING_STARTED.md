# Getting started with Proti

For a new implementation, follow the repository initializer instead of hardcoding Sanity IDs in source. See [Project Initialization](PROJECT_INITIALIZATION.md) for complete prompts and seeding rules.

## Prerequisites

The existing root README specifies **Node 24.19.0** and **pnpm 10.34.1**. A Sanity project/dataset and permissions to write to that dataset are required to seed content. The Web installation references a versioned local Mino UI tarball; check that the file and workspace lockfile are present in your checkout before installing.

## Setup

From the repository root:

```bash
pnpm install
pnpm proti:init
```

The initializer generates `proti.config.json`, `web/.env.local`, and `studio/.env.local`, and updates root/Web/Studio package names. It prompts for Sanity settings, Web/Studio URLs, Site identity, allowed domains, canonical domain, default locale, and supported locales.

Add the **secrets locally**, not to a committed file:

```dotenv
# web/.env.local — placeholders only
SANITY_API_READ_TOKEN=
SANITY_API_WRITE_TOKEN=
SANITY_REVALIDATE_SECRET=
```

`SANITY_API_WRITE_TOKEN` needs permission to create Site/starter documents. Never commit these values or send them in issue reports. Also set the appropriate local/nonsecret Sanity environment fields using the initializer.

Choose one seed mode:

```bash
pnpm proti:seed                    # Site only
# OR
pnpm proti:seed --starter-content # Site + default-locale Home/Header/Footer/Navigation
```

Seeding is designed to be idempotent/non-destructive. Then run:

```bash
pnpm proti:check
```

Start Studio and Web **in different terminals**, from the repository root:

```bash
pnpm dev:studio
pnpm dev:web
```

Typical URLs: Studio `http://localhost:3333` and Web `http://localhost:3000`. The Site's `domains` must include the hostname being used. Seeded content is minimal; add content through Studio.

## First editorial pass

1. Open **Site** and confirm supported locales, default locale, canonical domain, and SEO/Organization defaults.
2. Create or edit a locale's homepage under Pages; publish it.
3. Create Header/Footer and a Navigation Set, then assign it as the Site's default navigation for that locale.
4. Add page content blocks and publish. Check the public path and semantic headings.
5. If needed, add a second locale and create exact translations using the translation action.
6. Verify the language selector only offers pages that actually exist in another locale.

See [Editor Guide](EDITOR_GUIDE.md).

## Verify the installation

- `pnpm proti:check` reports environment/Site configuration readiness; starter pages are optional.
- Web at `localhost:3000` resolves the configured Site.
- Studio can open and publish documents.
- The production build and Playwright tests run as described in [Testing](TESTING.md).

## Common setup failures

| Symptom                                 | Check                                                                               |
| --------------------------------------- | ----------------------------------------------------------------------------------- |
| Homepage 404                            | Site domain host match, Site document, and a published homepage in that locale      |
| Studio refuses to start                 | `SANITY_STUDIO_PROJECT_ID` generated by init; check Studio env path                 |
| Sanity draft preview fails              | Read token, `NEXT_SANITY_STUDIO_URL`, Presentation preview URL, and allowed origins |
| Install fails on Mino dependency        | Actual `web/mino-ui-<version>.tgz` matches `web/package.json` and lockfile          |
| E2E routes return 404                   | Only enable routes in `web/e2e/.env.e2e` that exist in the dataset                  |
| Published changes stale on `pnpm start` | Production caching; verify deployed webhook rather than local Web server            |

See [Configuration](CONFIGURATION.md) for environment variable names and host behavior.
