# Proti v0.6.0 — Production Readiness, Performance & Developer Experience

Proti v0.6.0 focuses on making the Next.js + Sanity starter safer to operate and easier to adopt, with automated accessibility and performance safeguards and a streamlined developer workflow.

## Highlights

- **Production readiness:** Configuration and dependency-security review, plus improved Forms and Polls diagnostics.
- **Accessibility:** Deterministic desktop/mobile fixture-based WCAG A/AA checks; improved footer link target sizing.
- **Performance:** Lighthouse CI budgets with median desktop/mobile measurements, saved reports, and retained diagnostics on failure. Grid images now reserve layout space before loading.
- **Developer experience:** Offline Web/Studio environment preflight, grouped verification commands, expanded onboarding and component-extension documentation, and isolated clean-project regression coverage.

## Key commands

From the repository root:

```bash
pnpm proti:env:check          # Offline local configuration validation
pnpm test:proti:dx            # New-project and DX regression coverage
pnpm verify:quick             # Fast feedback (configuration, lint, types, tests)
pnpm verify:fixtures          # Deterministic visual/a11y/Grid checks
pnpm verify:performance       # Lighthouse budgets
pnpm verify:all               # Comprehensive developer verification
pnpm verify:all --dry-run     # Show commands without running them
```

`pnpm proti:check` remains the more comprehensive live Sanity/setup readiness check. CI preflight mode reads variables from the process environment rather than local `.env` files.

## Performance budget policy

Each of Hero, Grid, and Navigation is measured in Lighthouse three times on desktop and three times on mobile. Blocking checks use the median per fixture/profile:

| Metric                       | Policy                  |
| ---------------------------- | ----------------------- |
| Lighthouse Performance score | ≥ 90 (blocking)         |
| Largest Contentful Paint     | ≤ 2,500 ms (blocking)   |
| Cumulative Layout Shift      | ≤ 0.1 (blocking)        |
| Total Blocking Time          | ≤ 200 ms (warning only) |

These are **lab measurements**, not field Core Web Vitals or real-user INP.

## Upgrading from v0.5.0

- Align the root, Web, and Studio package versions at `0.6.0` and verify installation with `pnpm install --frozen-lockfile`.
- Keep `mino-ui` independently versioned; v0.6.0 does **not** require changing its tarball in this release-preparation patch.
- Review the environment preflight output and deployment settings. Do not enable `PROTI_VISUAL_FIXTURES=1` in production.
- Review updated visual snapshots when applying the approved Grid and footer changes; never auto-approve screenshot diffs blindly.
- No dependency or CMS schema changes are introduced **by this release-preparation patch**. Check other v0.6.0 feature commits for project-specific migration requirements.
