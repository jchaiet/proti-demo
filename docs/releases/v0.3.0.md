# Proti v0.3.0 — Release notes

**Status:** engineering regression and manual feature verification reported passed; **Git tagging/deployment audit not yet confirmed**. Version target: `0.3.0` for root Proti, Web and Studio packages. Mino UI is separately versioned and currently referenced as the local `mino-ui-0.0.3.tgz` dependency in `web/package.json`.

## Theme: locale-safe SEO and semantic discoverability

The v0.3 release concentrates on making the starter's published content more reliably understandable to browsers, search engines and answer systems, without inventing translations or editorial identity signals.

### Batch 1 — Locale and hreflang

- Default locale unprefixed, other locales prefixed; canonical redirect for an explicitly prefixed default locale.
- Exact Page and Blog translation lookup by Site plus path/slug; language alternates only where an equivalent exists.
- Locale-appropriate language tag generation and query-string preservation on language changes.

### Batch 2 — Canonical domain and Author locale integrity

- Site canonical domain as the authoritative origin for canonical URLs and supporting SEO endpoints.
- Author display localization held in one Author identity document.
- Author profile alternate links and indexing handled according to localized-field availability, instead of assuming all locales are complete.

### Batch 3 — Structured data and entity graph

- JSON-LD builders for Organization, WebSite, WebPage, Person, ProfilePage, BlogPosting, CollectionPage and BreadcrumbList.
- Stable entity IDs and links among Site, Page, Blog, Author/reviewer and breadcrumbs where applicable.
- Support for attributed professional credentials, affiliations, sources, reviews and editorial dates when backed by CMS content.

### Batch 4 — Semantic/GEO discoverability audit

- Studio content-quality validation for headings, accessible images and structured editorial details.
- SEO-output integration tests; inspectable server-rendered metadata and JSON-LD.
- Site robots/sitemap output and locale/canonical path validation.

## Verified regression summary

The release validation reported by the project owner includes Mino UI test/lint/build; Web tests/lint/typecheck/build; Studio tests/typecheck/build and separate lint validation; root starter tests plus `proti:check`; Playwright development and production suites; EN/ES routing, SEO/GEO, Search/Document Lists, Modal behavior and deployed Sanity revalidation. The final production Playwright suite was reported passing **30 tests**.

A runtime error (`translatedLocales is not iterable`) was found and corrected in Blog/Author resolvers during E2E testing, followed by a successful re-run. Mobile Search screenshot drift was traced to an older Next.js development-indicator baseline; approved screenshots were refreshed and subsequent runs passed. Keep these as regression examples, not as instructions to automatically rebaseline.

## Known boundaries and release verification

- SEO/structured data validity is not a guarantee of indexing, search placement, or AI citations.
- This documentation archive does **not** include a root `pnpm-lock.yaml`, the `web/mino-ui-0.0.3.tgz` payload, `.github` workflows, or the committed `.env.example` templates. Their **actual repository presence and correctness still require verification**, not a claim that they are absent from the real repository.
- The Studio source includes a `modal` translation implementation type, but `studio/sanity.config.ts` did not register the translation action for `modal` at the time of this source review. Confirm intended Modal editorial workflow before advertising that UI.
- The uploaded ZIP included a local E2E environment file, so credentials must be rotated if sensitive (rotation is being handled separately). This documentation-only ZIP intentionally excludes all environment files and application sources.
