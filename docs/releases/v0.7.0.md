# Proti v0.7.0 — Release Notes (Candidate)

**Release status:** Candidate; do not tag or publish until the [v0.7.0 release checklist](../RELEASE_CHECKLIST.md) is signed off, the intended release commit is deployed, and production smoke checks pass.

## Summary

v0.7.0 expands the composable Page Builder, adds conditional forms from Studio authoring to trusted API submission, and improves global-search request latency. It also includes Grid integration, Document List and form-upload safeguards introduced during development.

## Highlights

### Notice / Callout Block

Five display variants: neutral, information, success, warning and promotion. Supports optional icons and CTAs, rich-text heading/description and shared block styling. Available through Sanity on supported Page, Blog and reusable content surfaces.

### Metrics / Statistics Block

Responsive two-, three- and four-column metrics with default, card and divided presentations. Each metric has a text-based value, optional prefix/suffix, label and supporting text. Static values intentionally avoid animation-related accessibility and visual-regression concerns.

### Conditional forms

- Studio authors can configure one visibility condition per eligible field/fieldset based on a supported Select, Radio or Checkbox trigger. Supported comparisons are equals, not-equals and contains-selection.
- Conditional fields and nested fieldsets show/hide as visitor answers change; values for hidden fields are cleared and hidden required fields do not block progress.
- Multistep forms support conditions that reference eligible earlier-step answers. Unsupported forward references, conditional trigger chains and invalid configurations remain rejected by authoring validation.
- The submission endpoint independently evaluates conditions using the **published** Sanity definition, rejects unknown/disabled fields or invalid trigger answers, enforces visible required fields, and strips hidden field values before forwarding to configured webhooks.
- Form File Upload remains deliberately restricted: unsupported active upload controls cannot be newly published/used as if supported.

**Deployment dependency:** Deploy the updated **Web API before Studio**, so Studio cannot publish conditional forms against an older submission endpoint. Confirm the Web deployment is healthy before releasing the Studio changes.

### Search and Document List

- Global Search's published Host → Site lookup uses tagged Next.js caching with webhook invalidation and a 60-second fallback. Preview and local development bypass the cache; public API responses remain `Cache-Control: no-store`.
- The locale-aware search contract, result facets, type filters, sort options and pagination are retained.
- Document List search now waits after typing, prevents server response races from losing keystrokes and preserves expected URL/filter interactions. Taxonomy filtering and Grid image layout are covered by regressions.

## Observed search performance

The following figures came from the project's **local** before/after benchmark of the `first` query (two results). They are not guaranteed production timings.

| API case    | Before p50 | After p50 |  Difference |
| ----------- | ---------: | --------: | ----------: |
| Empty query |   135.3 ms |    8.3 ms | ~94% faster |
| Basic query |   280.2 ms |  159.1 ms | ~43% faster |

Other optimized benchmark cases were not supplied in the release conversation; do not invent numbers. The Batch 3C live contract check and full regression suite were **reported passing**. The measured dataset contains about ten fetched documents, so search-at-scale remains an observation for future work.

## Versions and dependencies

- Proti root, Web and Studio: target version **`0.7.0`**.
- Mino UI remains independently versioned: **`mino-ui-0.0.6.tgz`** is the expected Web local package at this release.
- After bumping Proti manifest versions, check `pnpm-lock.yaml`; synchronize it only if the package manager requires a change. Ensure the Mino tarball, Web manifest and lockfile agree.
- No public environment variables or secrets should be committed to the release.

## Migration / operator checks

1. Deploy Web before Studio; run an end-to-end test of a **published** conditional form and confirm that only visible fields reach the webhook.
2. Confirm invalid trigger values and forged hidden data are rejected/removed in accordance with the validation contract; verify existing nonconditional forms and polls still work.
3. Verify the Site revalidation webhook invalidates the Search Site cache on signed updates; verify `en-us` and configured alternate locale behavior and hostname isolation.
4. Ensure `PROTI_VISUAL_FIXTURES=1` is **not** enabled on deployed production builds; `/visual-fixtures/*` must return 404 publicly.
5. Run the canonical repo test flow: `pnpm install --frozen-lockfile`, `pnpm verify:all`, required GitHub Actions checks, and production smoke.
6. Review committed visual fixture baselines before the release; do not update screenshots simply to silence diffs.
